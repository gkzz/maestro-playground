# Maestro iOS Issue #3494 Investigation

## Environment

The investigation is run from GitHub Actions using `.github/workflows/e2e.yml`
on `macos-26`.

Default workflow inputs mirror the issue report:

- Maestro versions: `2.6.1` and `2.8.0`
- Xcode: `26.6`
- Runtime: `iOS 26.5`
- Device: `iPhone 17`
- Iterations per version: `3`
- Iteration timeout: `300` seconds
- App ID: `com.example.maestro3494`
- Default flow: `.maestro/investigations/ios_3494_springboard_crash.yml`

The workflow records `sw_vers`, `xcodebuild -version`, `xcode-select -p`,
`xcrun simctl list`, available runtimes, available device types, runner image
metadata, and `maestro --version` for each tested CLI version.

## Minimal App Fixture

The fixture in `fixtures/ios-springboard-crash` is a tiny Swift/UIKit app that
builds a Release simulator `.app` directly with `xcrun swiftc`.

It intentionally avoids React Native and Expo so the repro remains public and
small, but it keeps the issue's relevant surface:

- A release simulator app is installed and launched.
- The app exposes `App title` and `Visible sheet title`, matching the issue's
  minimal flow.
- A `WKWebView` is present so SpringBoard/XCTest loads WebKit accessibility
  bundles, matching the crash report boundary called out in the issue.
- A small label updates repeatedly to churn the accessibility tree during
  repeated hierarchy reads.

## Reproduction Steps

1. Open the `E2E` GitHub Actions workflow.
2. Run it with the default workflow dispatch inputs.
3. Compare the uploaded artifact directories under
   `artifacts/investigations/maestro-ios-3494/maestro-<version>/run-NNN/`.
4. Check `new-springboard-crashes.txt` for each run and copied `.ips` files
   under `springboard-crashes/`.
